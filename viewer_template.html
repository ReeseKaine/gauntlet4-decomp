How to read this

“Game graphics” is drawn by the game itself: the real ROM boots headless in an emulator, sets each level up with its own code (Arcade levels in Arcade mode, 81–8D as Battle arenas, 8E as the Quest hub, 8F onward as Quest area and stage), and the picture is read back from video memory, with every monster, generator and item drawn from its sprite settings. Two random steps the game applies at level start (a random pick among several cells of one kind, and bonus food per player) are skipped, so each picture matches the cell grid exactly. The yellow 1P marks the player start, which the game draws as floor.

Each map is the 32×32 grid that the game's decompressor (map_decode, ROM 0x19122) writes to $FFE246, decoded here by the C translation that matches the ROM bit for bit. “Raw” shows the decoded values 0–63; the other choices show them after one of the game's four remap tables, which is what the level builder actually reads.

Cell names come from the game code, not from guesses at the shapes: tile codes 00–2B from the touch-handler table at 0x67F0 and the pickup messages each handler prints; object codes 80–DF (packed as 1 tttt f ss: type, generator flag, level) from the per-frame object table at 0xA89E, whose entries call each monster's own intro text; FC from the level-start code that places player 1 there. Hover a legend row for the evidence. Quest objects are named from their code and sprites: C2/CA look like treasure but move and bite (mimics), D0–D3 are the four tower gems, D8 is an invisible effect trigger. Item 1F appears in no map and is still unidentified.

The “Arcade alt” table (0x25DC4) is used when $FFE790 is clear; levels marked with a dot use a different record from the main Arcade table. The source ROM is __ROM__.
